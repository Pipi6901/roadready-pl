# Контент: лицензия, импорт, переводы

Самая рискованная часть проекта. Код можно написать за пару месяцев — контент упирается в юридический процесс и в объём перевода.

---

## 1. Лицензия DVSA — критический путь релиза

Использование вопросов DVSA без лицензии — **уголовное правонарушение** (ТЗ 8.1). Лицензии нет, заявка не подана (ADR-007).

### Процесс
1. Заявка на GOV.UK: `https://www.gov.uk/guidance/reuse-dvsa-learning-materials`. Подача бесплатна.
2. Рассмотрение — 10 рабочих дней.
3. Видеозвонок с DVSA: обсуждение продукта и бизнес-плана.
4. Подписание Crown copyright licence agreement.
5. Получение банка: 730 вопросов с ответами, пояснениями и изображениями, 14 тем, симулированные hazard-клипы.
6. **Одобрение дизайна продукта со стороны DVSA до начала продаж.**

Отдельно существует **foreign language product licence** — тип лицензии для продуктов с переводом. Это ровно наш случай, запрашивать нужно сразу его. Переведённые продукты можно бесплатно продвигать на сайте Safe Driving for Life — заметный маркетинговый канал.

### Финансовые условия
Роялти **13% от net sales** ежеквартально, включая нулевые отчёты при отсутствии продаж. Закладывается в финансовую модель: при цене £4.99/мес и комиссии стора 15–30% на роялти уходит ещё 13% чистой выручки.

### Что делаем прямо сейчас
- **Подать заявку в первую неделю проекта.** Это не задача разработки, но она блокирует релиз сильнее любой задачи разработки.
- Пункт 6 (одобрение дизайна) означает, что макет и живая сборка должны быть готовы к показу DVSA к моменту звонка — ещё один аргумент не тянуть с заявкой.
- До подписания договора нигде — ни в приложении, ни в описании в сторе, ни в маркетинге — не используются формулировки «official questions», «official DVSA», «licensed by DVSA».

### Бесплатный источник, доступный уже сегодня
На GOV.UK по Open Government Licence v3.0 доступны 600+ изображений дорожных знаков (JPG и вектор). Лицензия DVSA для них не нужна, достаточно указать источник. Используем для демо-банка и для темы «Дорожные знаки».

## 2. Демо-банк на время разработки

Пока лицензии нет, разработка идёт на собственном наборе:

- ~50 вопросов по открытым правилам Highway Code, написанных самостоятельно.
- Изображения знаков из набора OGL v3.0.
- Покрытие: минимум по 3 вопроса в каждой из 14 тем — чтобы карта тем, разблокировка и статистика работали на реальных данных.
- Переводы на 2 языка (испанский и польский) — этого достаточно, чтобы отладить двуязычный режим, RTL проверяем отдельно на арабском.

Формат демо-банка **побайтово совпадает** с форматом импорта лицензионного пакета. Подмена контента после получения лицензии — операция в админке, а не задача разработки.

## 3. Импорт контента

Админка принимает CSV/Excel (FR-14). Структура файла:

| Колонка | Обязательна | Описание |
|---|---|---|
| `topic_slug` | да | привязка к теме, тема создаётся автоматически при отсутствии |
| `question_id` | да | стабильный идентификатор из источника, ключ для повторного импорта |
| `type` | да | `single_choice` / `case_study` / `hazard_video` |
| `question_en` | да | текст вопроса |
| `option_a…d` | да | варианты |
| `correct` | да | буква верного варианта |
| `explanation_en` | да | пояснение |
| `media_filename` | нет | имя файла из медиатеки |
| `subtopic` | нет | для расчёта слабейшей подтемы |
| `source_ref` | да | ссылка на первоисточник, нужна для лицензионной отчётности |

Правила импорта:
- Импорт идёт в **черновой** тест-сет, никогда сразу в опубликованный.
- Повторный импорт того же `question_id` обновляет вопрос и помечает все его переводы как `outdated`.
- Перед сохранением — валидация: заполнены обязательные поля, `correct` соответствует существующему варианту, `media_filename` есть в медиатеке. Отчёт об ошибках по строкам, частичный импорт запрещён.
- Публикация возможна только после прохождения валидации (см. [02-architecture.md](02-architecture.md), раздел 3).

## 4. Переводы — 9 языков

### Объём
730 вопросов × (вопрос + 4 варианта + пояснение) ≈ 120 слов на вопрос ≈ **88 000 слов на язык**, около **790 000 слов** на все девять. Это самая большая по объёму работа в проекте, и её нельзя недооценивать.

### Трёхуровневый подход

**Уровень 1 — машинный перевод (все 9 языков).**
Пакетный перевод через LLM с промптом, фиксирующим контекст: экзамен по вождению, британские реалии, сохранение точных числовых значений (ограничения скорости, дистанции), единый глоссарий терминов. Статус перевода — `machine`. Стоимость — десятки долларов на язык, срок — дни.

**Уровень 2 — глоссарий и обязательная вычитка терминов (все 9 языков).**
Составляется глоссарий из ~200 ключевых терминов (dual carriageway, hard shoulder, give way, MOT, tachograph…). Каждый термин вычитывается носителем, после чего машинные переводы прогоняются на соответствие глоссарию. Это закрывает главный риск: ошибка в термине меняет смысл правила.

**Уровень 3 — полная вычитка носителем (приоритетные языки).**
Полная вычитка 88 000 слов стоит порядка $2 600–4 400 за язык — на девять языков это неподъёмно для MVP. Решение: полная вычитка для **2–3 языков с наибольшим спросом** (по данным переписи UK 2021 — польский, урду, панджаби), остальные выходят на уровне 2 и вычитываются по мере роста установок.

В приложении для языков уровня 1–2 показывается корректная пометка о машинном переводе. Скрывать это нельзя.

### Панель статусов (FR-15)
Админка показывает по каждому языку: переведено / не переведено / устарело, с разбивкой по темам и возможностью открыть конкретный перевод на редактирование. Устаревшие определяются автоматически по расхождению `sourceHash`.

## 5. Медиа

- Изображения из лицензионного пакета и набора OGL. Обработка: приведение к WebP, два разрешения (1x и 2x), ограничение по ширине.
- Hazard-клипы — из лицензионного пакета, в MVP не публикуются (ADR-006). Для каждого клипа задаётся окно засчитываемой реакции `hazardWindow`.
- В медиатеке хранится тип лицензии каждого файла (`DVSA` / `OGL-v3` / `own`) — без этого невозможно корректно отчитываться и разделять контент по странам.
- Удаление медиа блокируется, если файл используется хотя бы одним вопросом.
