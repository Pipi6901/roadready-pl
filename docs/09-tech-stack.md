## 1. Expo SDK 57

SDK 56 вышел 21.05.2026, SDK 57 — 30.06.2026. Переход между ними намеренно не-ломающий (RN 0.85 → 0.86 без breaking changes), апгрейд одной командой. Ломающие изменения были в 56, не в 57.

Берём 57: к моменту релиза через 3–4 месяца он будет предыдущей стабильной версией, а 56 уйдёт за край окна поддержки. Откат на 56 при проблемах дешёвый.

**New Architecture обязательна начиная с SDK 55** — опция `newArchEnabled` удалена, легаси-архитектуры больше нет. Это главное ограничение при выборе библиотек: всё, что не портировано на TurboModules, работает только через переходный interop-слой.

Известные проблемы, которые нас касаются:
- Потребление памяти на Android при использовании reanimated выросло на 25–30% (изменение в Hermes из RN 0.85, SDK 56 задет так же). Обходится режимом worklets bundle.
- `jest-expo@57` конфликтует по peer-зависимостям с RN 0.86 — лечится `overrides` в package.json.

Минимумы: Xcode 26.4, iOS 16.4, Node 20.19.4.

## 2. Firebase — не на клиенте

**Офлайн-персистентность Firestore в React Native не работает.** Кэш JS SDK построен на IndexedDB, которого в RN нет, поэтому SDK молча переключается в память. Issue открыт с января 2024 и до сих пор не закрыт. Дополнительно: WebChannel в RN регулярно ломается и требует принудительного long-polling с потерей производительности, а модуль Firestore — самый тяжёлый в пакете.

Это не проблема для нас, а **подтверждение решения ADR-004**: банк вопросов и прогресс живут в SQLite, а контент приходит файлом. Firestore офлайн нам и не нужен.

**Решение:** Firebase-клиент в приложение не ставим вообще. Контент-пакет качается через `expo-file-system` по подписанной ссылке с CDN — при таком подходе хранилище может быть любым, что усиливает аргумент за Cloudflare R2 (OQ-3). Firestore остаётся серверной стороной: контент, админка, фича-флаги и версии пакетов.

Если Firebase-клиент всё же понадобится — только `@react-native-firebase` 25.x с нативными SDK, не JS SDK. Но это тянет обязательный dev-client, вес бандла и interop-риск: библиотека ещё не портирована на TurboModules напрямую.

⚠️ Поддержка New Architecture у Amplitude RN не подтверждена официально — проверить в спайке.

## 3. Подписки — Adapty 3.17.2

### Жёсткий дедлайн Google
**С 31.08.2026 все новые приложения и обновления обязаны использовать Google Play Billing Library 8**, продление по заявке — до 01.11.2026. Наш релиз попадает ровно за эту черту. PBL 7 в стор не пройдёт. Это не рекомендация, а условие публикации.

### Почему Adapty, а не RevenueCat

| | Adapty 3.17.2 | RevenueCat 10.4.4 |
|---|---|---|
| New Architecture | маркеры `isNewArchitectureEnabled` и `codegenJavaPackageName` присутствуют | **нет `codegenConfig`, нет TurboModule-спеки** |
| Открытые баги под New Arch | не найдено | `NativeModules.RNPurchases is null`, issue #1739 открыт с 22.04.2026, воспроизводится стабильно |
| Expo config plugin | есть | **отсутствует** |
| Бесплатный порог | до $5 000 MTR | до $2 500 MTR |
| Дальше | 1% выручки | 1% от gross |
| PBL 8 | ⚠️ заявлен, но не подтверждён — проверить | подтверждён (purchases-hybrid-common 18.22.2) |

Решающий аргумент — New Architecture обязательна в SDK 57, а у RevenueCat нет TurboModule-спеки и есть открытый баг с полным отказом модуля. Плюс у нас уже есть опыт интеграции Adapty на другом проекте.

**Берём линию 3.x, а не 4.x.** Версия 4.0.0 вышла 13.07.2026 — ей неделя, и 4.0.1 уже чинил краш релизной сборки. При этом 3.17.2 вышла 18.07.2026, то есть **позже** 4.0.1: линия 3.x активно поддерживается под тегом `latest-3`. Миграция на новую концепцию Flow — после запуска.

⚠️ **Версию PBL проверить эмпирически** в собранном APK: `./gradlew :app:dependencies | grep billing`. В v4 зависимость идёт через BOM, конкретная версия оттуда не видна, а релиз-ноты нативного SDK противоречат друг другу. При дедлайне 31.08.2026 верить на слово нельзя.

`expo-iap` и `react-native-iap` не рассматриваем: оригинальные репозитории заархивированы в апреле 2026, и это чистые клиентские обёртки — без аккаунтов нам пришлось бы самим строить хранилище прав доступа и серверную валидацию чеков.

**Спайк на 1 день до написания продуктового кода:** dev-build на SDK 57 с New Architecture, проверить, что модуль виден, провести реальную покупку в песочнице, убедиться в PBL 8 в APK. Биллинг держим за собственной абстракцией в одном модуле — смена вендора должна стоить день, а не неделю. `react-native-purchases-ui` не ставим ни при каком выборе: пейволл рисуем сами, тем более он уже есть в макете.

## 4. Медиа и офлайн

### expo-video вместо expo-av
`expo-av` окончательно мёртв: отсутствует в списке нативных модулей SDK 55, 56 и 57, документация отдаёт 404, патчи не выпускаются. Использовать нельзя.

**Точность замера тапа в hazard perception — читать свойство, а не слушать событие.** На New Architecture `player.currentTime` — синхронный JSI-геттер прямо в нативный плеер, его и читаем в обработчике тапа. Событие `timeUpdate` по умолчанию вообще не эмитится (интервал `0`), а при включении троттлится нативным observer'ом — на нём тайминг строить нельзя, только прогресс-бар. `seekTolerance` по умолчанию 0/0, то есть seek фрейм-точный из коробки.

⚠️ Физический потолок точности — около одного кадра (~33 мс при 30 fps) плюс латентность вызова на слабом Android. **Замерить на бюджетном устройстве до фиксации порогов скоринга**, окна засчитываемой реакции задавать с запасом.

### Озвучка — предгенерированные файлы, а не системный TTS
FR-07 говорит про системный TTS, но у `expo-speech` набор ограничений, которые бьют именно по нашему сценарию: на Android нет `pause()`/`resume()`; на iOS при включённом беззвучном режиме звук не воспроизводится **без ошибки** — пользователь просто получает тишину; на Android список голосов пуст, если TTS-движок не установлен, что не редкость на бюджетных и не-GMS устройствах.

**Решение:** аудио генерируется заранее и кладётся в контент-пакет, воспроизводится через `expo-audio`. Это даёт одинаковое звучание на всех устройствах, гарантированный офлайн и предсказуемое качество.

Важно: озвучивается **только английский оригинал** (ТЗ 10.5 — озвучка на языке оригинала), а не девять переводов. Значит объём предгенерации — один язык: 730 вопросов × ~20 секунд ≈ 60 МБ при разумном битрейте. На фоне 400 МБ пакета это дёшево.

`expo-speech` остаётся фолбэком для строк, которых нет в предгенерации.

### Загрузка контент-пакета
`File.createDownloadTask()` с колбэком прогресса, паузой и возобновлением. Метод `savable()` и `DownloadTask.fromSavable()` позволяют возобновить загрузку **после перезапуска приложения** — критично для 400 МБ на мобильной сети.

Пакет чанкуется: сначала вопросы и переводы, затем изображения, затем аудио, затем hazard-видео. Обучение разблокируется после первого чанка, остальное догружается фоном. Перед стартом проверяется `Paths.availableDiskSpace`.

### 🚩 Исключение из бэкапа — отдельная задача
Каталог `Paths.cache` iOS вычищает под давлением памяти, поэтому обязательный офлайн-контент там держать нельзя. Каталог `Paths.document` персистентен, но **по умолчанию попадает в iCloud-бэкап** — 400 МБ перекачиваемого контента в бэкапе это классическая причина реджекта по iOS Data Storage Guidelines.

При этом `expo-file-system` **не предоставляет API для исключения из бэкапа** — нужен собственный config-плагин, выставляющий `NSURLIsExcludedFromBackupKey` на директорию пакета, с переустановкой флага после записи. Заложено 2–3 дня в фазе 1.

**Важное разделение (уточняет ADR-002):**

| Что | Где | Бэкап |
|---|---|---|
| Контент-пакет, ~400 МБ | отдельная поддиректория в `Paths.document` | **исключён** — перекачивается с CDN |
| База прогресса, единицы мегабайт | `Paths.document` | **включён** — именно так прогресс переживает смену устройства |

Это не противоречие: перекачиваемое из бэкапа исключаем, невосстановимое — оставляем.

### expo-sqlite
Подходит без оговорок: ~800 вопросов и статистика — тривиальная нагрузка. Асинхронный API, prepared statements, миграции через `PRAGMA user_version`, WAL включаем сразу. Преднаполненная база поставляется через `assetSource` (⚠️ метода `importDatabaseFromAssetAsync` в текущем API нет — гайды с ним устарели). Полнотекстовый поиск при необходимости включается флагом `enableFTS` в config-плагине.
