# Архитектура

Ключевой принцип из ТЗ 4.1: **страна и язык — две независимые оси**. Добавление языка не трогает контент страны, добавление страны не требует пересборки приложения (FR-01, FR-02, FR-04).

---

## 1. Состав системы

| Компонент | Назначение |
|---|---|
| Мобильное приложение | React Native + Expo, iOS и Android из одной кодовой базы |
| Firestore | Контент: страны, тест-сеты, темы, вопросы, локали, переводы, UI-строки |
| Cloud Functions | Сборка и публикация контент-пакетов, вебхуки биллинга, генерация «Вопроса дня» |
| Объектное хранилище + CDN | Контент-пакеты и медиа (изображения, hazard-клипы) |
| Веб-админка | Управление контентом, импорт из CSV/Excel, статусы переводов |
| Слой подписок | Кросс-платформенный биллинг, валидация чеков, вебхуки |
| Amplitude | Продуктовая аналитика |

## 2. Модель данных (Firestore)

Все коллекции поддерживают мягкое удаление: поле `deletedAt` (FR-16). Ничего не удаляется физически.

### `countries/{countryCode}`
```
code            ISO 3166, напр. "GB"
name            "United Kingdom"
flagEmoji       "🇬🇧"
authority       "DVSA"
legalNotice     дисклеймер и указание лицензии (NFR-11)
testTypes       ["car"]                 в MVP только легковые
status          active | coming_soon | archived
questionCount   денормализованное число для экрана выбора страны
defaultLocale   "en"
sortOrder       порядок в списке
deletedAt
```

### `countries/{countryCode}/testsets/{testSetId}`
```
version         "UK-2026"
status          draft | published | archived
effectiveFrom   дата вступления в силу
archivedAt
versionHash     хеш содержимого — по нему приложение понимает, что пакет устарел
bundleUrl       ссылка на собранный пакет
bundleSize      размер в байтах, показывается пользователю перед загрузкой
publishedAt, publishedBy
deletedAt
```

Одновременно опубликован ровно один тест-сет на страну. Публикация нового автоматически архивирует предыдущий.

### `.../testsets/{testSetId}/topics/{topicId}`
```
name            "Road Signs"
slug            "road-signs"
icon            имя иконки
sortOrder       порядок в маршруте обучения
color           токен акцентного цвета темы
deletedAt
```

### `.../topics/{topicId}/questions/{questionId}`
```
type            single_choice | case_study | hazard_video
text            текст вопроса на английском
options         [{ id: "A", text }, { id: "B", text }, ...]
correctOptionId "C"
explanation     пояснение на английском
mediaId         ссылка на медиа или null
subtopic        "Overtaking" — для расчёта слабейшей подтемы
sourceRef       ссылка на первоисточник (нужна для лицензионной отчётности)
sortOrder
deletedAt
```

### `locales/{localeCode}`
```
code            BCP 47: "pl", "ur", "pa", "hi", "es", "es-419", "pt", "pt-BR", "ar"
nameNative      "Polski"
nameEnglish     "Polish"
direction       ltr | rtl
status          active | hidden
sortOrder
```

### `.../questions/{questionId}/translations/{localeCode}`
```
text            переведённый вопрос
options         [{ id: "A", text }, ...]
explanation     переведённое пояснение
status          not_started | in_progress | ready | outdated
sourceHash      хеш английского оригинала на момент перевода
translatedBy    machine | human
reviewedBy, updatedAt
```

`status: outdated` выставляется автоматически: при изменении английского оригинала пересчитывается `sourceHash`, и все переводы с несовпадающим хешем помечаются устаревшими. Это и есть панель статусов из FR-15.

### `uiStrings/{localeCode}`
Переводы интерфейса, не зависят от страны. В MVP заполнен только `en`, но структура заложена (ТЗ 4.1).

### `media/{mediaId}`
```
type            image | video
filename, storagePath, cdnUrl
width, height, durationMs      для hazard-клипов
hazardWindow    { startMs, endMs }  окно засчитываемой реакции
usedByQuestions [ ... ]        для контроля перед удалением
licence         "DVSA" | "OGL-v3" | "own"
deletedAt
```

### `dailyQuestions/{YYYY-MM-DD}`
Заранее выбранный «Вопрос дня» на страну — чтобы push и открытый по нему экран показывали одно и то же (ТЗ 8.5).

## 3. Доставка контента

Поштучное чтение Firestore из приложения не используется: 800 вопросов × 10 языков — десятки тысяч документов на каждую установку. Вместо этого — сборка пакета (ADR-004).

### Публикация
Нажатие «Опубликовать» в админке запускает Cloud Function:

1. Проверка целостности: у каждого вопроса есть верный вариант, пояснение и валидная ссылка на медиа; ни один опубликованный перевод не в статусе `outdated`.
2. Сборка файлов:
   ```
   bundles/{country}/{testSetId}/{versionHash}/
     manifest.json              версия, хеши частей, размеры, список медиа
     content.json               темы + вопросы на английском
     translations/pl.json       перевод целиком, один файл на язык
     translations/ur.json
     ...
   ```
3. Расчёт `versionHash`, заливка в хранилище за CDN, обновление `testsets/{id}`.
4. Архивация предыдущего тест-сета.

### Загрузка в приложении

**Первый запуск:** пакет качается чанками в порядке приоритета — сначала `manifest.json`, `content.json` и файл перевода выбранного языка, затем изображения, затем аудио озвучки, последними hazard-видео (NFR-04). **Обучение разблокируется после первого чанка**, остальное догружается фоном: заставлять пользователя ждать 400 МБ на экране онбординга нельзя.

Загрузка возобновляемая и переживает перезапуск приложения — на мобильной сети обрыв при таком объёме не исключение, а норма. Перед стартом проверяется свободное место на устройстве.

**Дальше:** приложение работает офлайн полностью (FR-05).

**Обновление:** при наличии сети сверяется `versionHash` из манифеста. Изменилось — догружаются только изменившиеся части (дельта по хешам, ТЗ 4.2).

**Смена языка:** скачивается только `translations/{locale}.json` — несколько сотен килобайт. Основной контент не перезагружается (FR-02, ТЗ 8.2). Именно поэтому переводы вынесены в отдельные файлы.

**Смена страны:** новый пакет целиком, с подтверждением объёма (ТЗ 8.1).

### Хранилище медиа
NFR-03 допускает до 400 МБ контента на пользователя. Исходящий трафик Google Cloud ≈ $0.12/ГБ: 10 000 загрузок ≈ 4 ТБ ≈ $480/мес только за раздачу. У Cloudflare R2 egress бесплатный — те же объёмы обходятся в единицы долларов за хранение. Рекомендация: метаданные в Firestore, пакеты и медиа — в R2 за CDN (открытый вопрос OQ-3).

## 4. Данные на устройстве

| Что | Где | Почему |
|---|---|---|
| Контент-пакет (JSON, изображения, аудио, видео) | Отдельная поддиректория каталога документов, **исключённая из бэкапа** | Большой объём, читается напрямую |
| Прогресс, ответы, статистика, очередь повторения | Локальная БД (SQLite) | Нужны выборки и агрегаты: точность по темам, слабейшая подтема, очередь Weak Spots |
| Настройки: страна, язык, дата экзамена, уведомления, скорость озвучки | Лёгкое key-value хранилище | Маленькие значения, читаются при старте |
| Статус подписки | Кеш слоя биллинга | Источник истины — сторы, локально только кеш для офлайн-режима |

Схема прогресса:

```
question_progress   question_id, country_code, attempts, correct_count,
                    last_answer, last_answered_at, mastered, in_review_queue
lesson_progress     topic_id, lesson_index, status, correct_count, completed_at
topic_stats         topic_id, mastered_count, accuracy, weakest_subtopic
mock_attempts       started_at, finished_at, score, passed, per_topic_json
daily_activity      date, lessons_completed, xp_earned, goal_met
user_state          total_xp, streak_days, streak_last_date, exam_date, first_launch_at
```

### Что попадает в бэкап, а что нет

Разделение принципиальное, две директории ведут себя противоположно:

| Что | Бэкап | Почему |
|---|---|---|
| База прогресса, единицы мегабайт | **включена** | Невосстановима. Именно так прогресс переживает смену устройства при отсутствии аккаунтов (ADR-002) |
| Контент-пакет, до 400 МБ | **исключён** | Перекачивается с CDN. 400 МБ в iCloud-бэкапе — классическая причина реджекта по iOS Data Storage Guidelines |

`expo-file-system` не даёт API для исключения из бэкапа — нужен собственный config-плагин, выставляющий `NSURLIsExcludedFromBackupKey` на директорию пакета, с переустановкой флага после записи файлов. Заложено в фазу 1, детали в [09-tech-stack.md](09-tech-stack.md), раздел 4.

Кэш-каталог для контента не подходит: iOS вычищает его под давлением памяти, а офлайн-режим обязан работать всегда.

## 5. Слои приложения

```
app/                маршруты Expo Router — только композиция экранов
components/         переиспользуемые UI-элементы, без бизнес-логики
features/
  learning/         уроки, подача вопросов, XP, серия
  practice/         mock-тест, quick quiz, weak spots, hazard
  content/          загрузка пакета, версии, доступ к вопросам
  progress/         запись ответов, статистика, достижения
  subscription/     статус подписки, лимиты free, пейволл
  settings/         настройки и их применение
services/
  db.ts             локальная БД
  storage.ts        key-value настройки
  content-sync.ts   загрузка и обновление пакетов
  tts.ts            озвучка
  notifications.ts  напоминания и «Вопрос дня»
  analytics.ts      Amplitude
  billing.ts        подписки
theme/              токены, светлая и тёмная палитра
```

Правила:
- Экран не ходит в сеть и в БД напрямую — только через `features/*`.
- Ни одного цвета в компонентах, только токены темы (ТЗ 10.2).
- Все тексты интерфейса — через словарь UI-строк, даже если интерфейс пока только английский.
- Доступ к вопросам всегда идёт через слой контента: он сам решает, отдавать перевод или нет, в зависимости от языка и тарифа.

## 6. Нефункциональные требования и как они обеспечиваются

| Требование | Решение |
|---|---|
| NFR-01: холодный старт ≤ 2 с | Splash не ждёт сеть; контент читается лениво; проверка обновлений — фоном после первого экрана |
| NFR-02: инсталлятор ≤ 300 МБ | В сборку не входит ни один вопрос и ни одна картинка — всё качается после установки |
| NFR-03: контент UK ≤ 400 МБ | Изображения в WebP, hazard-видео — по требованию, а не в основном пакете |
| NFR-04: полноценный офлайн | Пакет на устройстве; hazard-видео помечены как требующие загрузки |
| NFR-05: ответ API p95 < 500 мс | Статические файлы за CDN вместо запросов к БД |
| NFR-06: GDPR | Аккаунтов и PII нет (ADR-002); аналитика — обезличенная, с возможностью отключить |
| NFR-07: доступность | VoiceOver и TalkBack, подписи ко всем элементам, состояния не только цветом |
| NFR-08/09: версии ОС и экраны | iOS 16+, Android 8+, проверка от 360 dp до iPhone 16 Pro Max |
| NFR-10: тёмная тема | Семантические токены с первого дня (ADR-008) |
| NFR-11: юридические дисклеймеры | Экран About: Crown Copyright, Open Government Licence, ссылки на документы |
| NFR-12: правила подписок Apple | Пейволл с явной ценой, периодом, условиями автопродления и отменой |
